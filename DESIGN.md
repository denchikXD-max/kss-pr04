## 4. Проєктні рішення

| Питання | Рішення та обґрунтування |
|---|---|
| Як змінюється стан ресурсу (дія)? | Дії, які переводять сутність в інший життєвий стан і не є простим оновленням окремих полів (наприклад, повернення книги), моделюються як sub-resource дія за допомогою методу `POST` на шлях `/loans/{loanId}/return`. В OpenAPI така операція помічається розширенням `x-kss-action: true` та повертає статус `200 OK` із оновленим об'єктом позики. Якщо клієнт намагається повернути книгу, яка вже має статус `returned`, сервер повертає статус `409 Conflict`, оскільки операція конфліктує з поточним станом ресурсу. |
| Які методи ідемпотентні у вашому API? | Ідемпотентними є методи `GET`, `PUT`, `DELETE` та `HEAD`: повторний виклик методу призводить до того ж стану системи, що й одинарний. Метод `POST` неідемпотентний. Якщо через збій мережі клієнт повторить запит `POST /loans` або `POST /books`, для уникнення створення дублікатів сервер може підтримувати заголовок `Idempotency-Key` від клієнта або перевіряти бізнес-унікальність (наприклад, інвентарний номер примірника чи номер квитка) та повертати `409 Conflict`. Часткове оновлення `PATCH` у нашому дизайні є умовно ідемпотентним завдяки заголовку `If-Match`. |
| Як версіонується API? | API версіонується в URL шляху: `/api/v1`. Це забезпечує прозору маршрутизацію через reverse proxy (Nginx, Envoy) та очевидність версії для розробників клієнтських застосунків. Несумісними змінами (breaking changes) вважаються: перейменування або видалення існуючих полів, зміна типів даних, зміна структури або кодів відповідей, додавання нових обов'язкових полів у тіло запитів. Сумісні зміни (додавання необов'язкових полів або нових маршрутів) впроваджуються в рамках v1. |
| Формат помилок | Усі помилки клієнта (4xx) та сервера (5xx) повертаються у стандартизованому форматі **Problem Details for HTTP APIs (RFC 9457)** із заголовком `Content-Type: application/problem+json`. Схема містить поля: `type` (URI з описом типу помилки), `title` (короткий зрозумілий опис), `status` (числовий HTTP-код), `detail` (деталізація помилки) та `instance` (URI запиту). Для помилок валідації вхідних даних (422) схема розширюється масивом `errors: [{ field, message }]`. |
| Як клієнт дізнається адресу створеного ресурсу? | При успішному створенні сутності методом `POST` сервер повертає HTTP-код `201 Created` і обов'язковий стандартний заголовок `Location`, що містить відносний або абсолютний URI створеного ресурсу, наприклад: `Location: /api/v1/books/42`. Додатково тіло відповіді містить повне представлення створеного ресурсу у форматі JSON. |
| Які операції підтримують умовні запити (ETag)? | Операція читання детальної інформації про книгу `GET /books/{bookId}` повертає заголовок `ETag: "w/..."`. Клієнт може передати збережений ETag у заголовку `If-None-Match`, і якщо книга не змінювалась, сервер поверне легковагову відповідь `304 Not Modified` без тіла, заощаджуючи трафік. Для операції `PATCH /books/{bookId}` підтримується захист від конфліктів одночасного редагування ("lost update") за допомогою заголовка запиту `If-Match`. Якщо ETag клієнта застарів, сервер повертає `412 Precondition Failed`. |

### Додаткове проєктне рішення: План еволюції та переходу на `/api/v2`

У разі необхідності несумісної зміни (наприклад, перейменування поля `publicationYear` -> `yearPublished` або об'єднання полів читача):
1. **Анонс та заголовки знецінення:** У відповідях застарілого API `/api/v1` сервер починає повертати стандартизовані HTTP-заголовки:
   - `Deprecation: @1767225600` (або `true` за RFC 9457 / IETF draft) — повідомляє, що версія API застаріла;
   - `Sunset: Wed, 01 Jul 2027 00:00:00 GMT` — точна дата повного відключення старої версії;
   - `Link: </api/v2/books>; rel="successor-version"` — посилання на документацію та новий маршрут версії v2.
2. **Паралельна робота:** Нова версія `/api/v2` розгортається паралельно з `/api/v1`. Клієнтам надається перехідний період (наприклад, 6 місяців) для планової міграції на v2.
3. **Моніторинг та виведення з експлуатації:** Метрики звернень до `/api/v1` фіксуються сервером. Після настання дати з заголовка `Sunset` ендпоінти `/api/v1` вимикаються і повертають `410 Gone` із посиланням на `/api/v2`.
